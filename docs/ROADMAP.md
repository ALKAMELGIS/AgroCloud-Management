## 2. Excel import, checked on real workbooks

The importer was run on the farm's original harvest, EC/pH, fertigation, PPP data and PPP application workbooks against a database with every migration applied, then run again. Every row-based workbook imports in full (sheets that repeat another sheet are left out, total lines are skipped, wrong cells are listed with sheet and row) and the second run adds nothing. The detailed figures and the cells to correct stay with the farm team, not in this public repository. The day-by-house irrigation & fertigation record needs its own reader (section 5).

## 3. Code: one shape for every feature

Target tree (move a feature when it is next touched; no big-bang rewrite):

```
src/
  app/            shell, routes, providers, theme
  features/
    harvest/      pages/, components/, api.js, hooks.js, __tests__/
    ecph/  fertigation/  irrigation/  ipm/  gis/  settings/  import/ …
  shared/         ui kit (Card, Row, Meter, ModuleIcon), utils, i18n
backend/src/
  api/v1/         routes: auth, role checks, input validation only
  services/<area>/  business rules (import/ is the model to follow)
  repositories/   SQL only, one file per table group
  db/migrations/  numbered, each with a .down.sql
```

Rules:

1. A route file checks access and input, then calls a service. No SQL in routes.
2. No file over 600 lines. Split first: `PesticideApplications.js` (3,035), `BiologicalControlRecord.js` (2,510), `ManpowerRecord.js` (2,015), `BumbleBees.js` (1,972), `HarvestEntry.js` (1,790); backend `ipm.service.ts` (2,237), `manpower.service.ts` (1,993), `gisLayer.service.ts` (1,624).
3. Every rule that protects data (limits, PHI, tenancy) lives in the database or a service, with a test.
4. Root folder holds only config and README; guides live in `docs/` (done in this round).

## 4. Database: clear and safe

1. Keep `docs/DATABASE.md` current: run `scripts/db-map.py` after each migration.
2. Natural keys as unique indexes, so a duplicate can never be written by any path: harvest (field, date, batch, segment, quantity, start time), EC/pH reading (field, date, time), fertigation (field, date, water, fertilizer), spray (field, date, product, start time). Clean existing duplicates first, then add the indexes.
3. Tenancy check on tables without `organization_id` that are not reached through a field or user: `field_types`, `recipes`, `crops`, `scheduled_reports`, `shift_templates`, `manpower_activities`, `attachments`, `gps_positions`. For each: either global by design (write it down) or add the column.
4. Every migration gets a `.down.sql`; a CI job applies all migrations to an empty PostgreSQL + PostGIS and runs the import check above.
5. Naming: plural snake_case tables, `<thing>_id` keys, units in column names where they matter (`water_m3`, `area_ha`).
